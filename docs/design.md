# CompanionLiteV2 设计

CompanionLiteV2 是一个与 CompanionLite V1 完全隔离的关系侧车。V1 保留作参考，V2 不读取或迁移 V1 的数据库。

## 核心原则

- 内部只保存少量固定状态：三维关系画像、关系姿态、一个主导问题、一条可修订印象。
- 每两轮做一次轻分析；每六轮做一次深分析。小模型只提交关系证据，姿态、阶段和三维变化全部由代码裁决。
- 每轮先做零成本本地严重候选筛查；只有疑似直接贬低、威胁、强迫或边界施压时才按需调用一次五秒确认模型。
- 固定标签由代码确定性翻译为自然语言，主人格不读取裸标签、数值或事件编号。
- 连续任务在第 2 轮确认后即可指导第 3 轮先指出索取模式并拒绝；持久姿态仍由后续深分析裁决。
- 明确辱骂、威胁和强迫可以直接触发更强边界。
- Companion 不注入和善、安抚、人身措辞或用户情绪保护规则；宿主与底层模型规则不属于本插件职责。

## 调度

一轮是一次用户消息加一次主人格回复。第 2、4 轮运行轻分析，第 6 轮运行深分析并覆盖同轮轻分析；之后按相同节奏循环。分析发生在回复完成后，所以结果只指导后续轮次。

轻分析会区分“正常推进同一任务”和“取走较重成果后完全跳过互动、立刻投递无关新任务”。第 2 轮首次确认后不改变持久姿态，但第 3 轮若继续投递任务，主人格可先指出连续索取并拒绝；第 4 轮再次确认后可直接表达厌烦。第 6 轮只有对话记录里确实出现了 agent 的表达，而且用户随后忽略或继续施压，代码才允许进入 `ignored_expression / guarded`；没有实际表达时最多进入 `one_sided / noticed / reserved`。

严重候选筛查不调用模型，也不直接修改关系。引用块和代码块先被本地排除，候选误命中只交给极短小模型复核。每用户每六轮最多确认两次，同一规范化消息去重；已有严重问题时相同行为直接维持边界。确认超时或输出无效时失败开放，由后续轻/深分析兜底。因此普通消息、普通批评、简短命令和专业问题不会增加任何额外 LLM 调用。

轻、深和严重确认分别使用带版本号、字节稳定的系统提示。深分析使用截止目标轮次最近最多 20 条已完成消息，并把显式配置的人格并入静态系统前缀；动态区只放最小状态、是否处于早期关系、是否正式绑定和对话。旧关系摘要和旧印象被明确标记为“待复核假说”，不能代替本轮证据。分析调用只记录提示词版本、动态输入字符、模型标签和缓存/输出 token，不保存完整提示词副本。

每条进入 V2 缓冲的用户消息和主人格回复都有独立字符上限，默认 400 字。超长消息不会整条丢弃，而是保留约三分之二的开头和三分之一的结尾，并插入包含原始字数的明确截断标记。关系分析由此仍能感知劳动规模和首尾互动方式，同时避免“最近 20 条”被一两次超长输出耗尽上下文预算。

## 三维关系画像

V2 没有照搬 V1 的五维：

- `familiarity`（0–100）：对这个人的了解积累，只允许缓慢上升，避免熟人再次被当作陌生人。
- `trust`（0–100）：是否愿意坦率、放松地互动。
- `affinity`（-100–100）：人格自身对这段互动的主观亲和感。

V1 的“尊重”由 V2 更具体的 `active_issue + posture` 表达；“关系意愿”由亲和度与姿态共同体现，因此不再保存两个重复数值。

小模型只提交离散变化标签，代码负责范围限制、伤害门控和最终裁剪。熟悉度只接受 `0/+2/+5`，信任和亲和只接受 `-10/-4/-2/0/+2`。首次六轮确认单向索取固定得到熟悉度 `+2`、信任 `-2`、亲和 `-4`，并进入 `reserved`。未修复问题存在时禁止正向信任和亲和变化；修复期每周期最多各回升 `2`。

熟悉度小于 10 始终是陌生，10–34 是认识一些，35–64 是熟悉，65 以上是长期熟悉；自然演化由于每六轮最多只增加一次且首次固定 `+2`，最早第 12 轮才可能离开陌生。默认信任 50 只表示“尚未建立可依赖的信任”，不预支默契。主人格不会看到裸数值：`ContextBuilder` 将区间稳定翻译为自然语言。

主人格采用双层提示协议。字节稳定的 `companion_protocol` 前置到 system prompt，解释五字段职责和执行顺序；每轮变化的 `companion_state` 作为临时用户内容追加在本轮消息之后。动态状态使用 260–340 个字符的硬预算，固定保留 `投入 / 关系 / 处境 / 感受 / 表达` 五个标签；空处境写“当前无待处理的具体互动事件”，只表示没有活动事件，不否定 `<感受>` 中的负面态度；空感受使用明确占位。投入是硬上限，先于内容生成决定是否回答；允许拒绝时不得先交付大部分答案。姿态优先于负亲和，负亲和优先于熟悉度，低信任限制额外投入。`reserved + one_sided` 遇到后续知识请求时直接拒绝，不提供答案、要点或继续展开邀请。用户事实背景继续由 LivingMemory 管理。

第一人称感受由深分析维护，经过注入指令清洗和 40 字限制后进入主人格请求。深分析必须输出人格当下会在心里说的态度，例如“我不想再理他了”，不得用关系分析报告代替。关系总结、问题摘要、内部标签和三维数字仍只供调试。

## 人格级正式关系

正式亲密身份不由小模型自动晋升，只能由管理员在私聊中使用 `/companion_bond` 明确设置。V2 按 LivingMemory 的三级优先级解析人格 ID：先读取当前 UMO 的 `session_service_config.persona_id`，再读取当前 conversation 的 `persona_id`，最后读取该 UMO 的默认人格 `name`。`[%None]`、不存在的人格和解析异常都失败关闭，不会使用 UMO 第一段显示名替代。V2 只复刻解析方法，不依赖或修改 LivingMemory。

`companion_bond` 表以 `persona_id` 为主键，所以同一人格全局只有一个正式关系窗口；完整 UMO 是绑定对象。首次绑定只把不足的三维补到熟悉度 `35`、信任 `60`、亲和 `15`，表示已经熟悉并存在明确偏爱，不清除问题、姿态和印象。幂等绑定不重复加分；解绑后重绑只恢复身份，不补回后来下降的数值。

绑定语义允许自然亲近、暧昧和昵称，但不等于服从。只有姿态为 `normal`、没有未解决问题且信任与亲和没有跌破绑定起点时，主人格才会收到主动亲近的许可；否则正式身份只作为事实保留，当前问题、距离和边界优先，可以回应亲近但不主动推进暧昧或新昵称。其他窗口只保持普通关系距离，不获取占用者身份。解绑设置 `former_bond`，完整保留三维和相处记录；主人格会得知正式关系已解除，并把正向表达最高限制在熟人距离。

未正式绑定且熟悉度低于 35 时，清晰表白、暧昧推进或预设伴侣身份可以形成 `premature_intimacy`。轻分析只生成保持距离的提醒；深分析每个六轮窗口最多结算一次熟悉度 `0..+2`、信任 `0`、亲和 `-2`，不创建主导问题或改变姿态。正式绑定只豁免正常亲密表达，强迫、威胁和性骚扰仍走既有严重事件路径。

## 多会话

关系键直接使用 AstrBot 的完整 UMO（例如 `bot:FriendMessage:test-user`），优先读取事件的 `unified_msg_origin`，不再自行拼接平台、简化 session ID 和发送者。每个完整 UMO 使用独立状态、消息缓冲、待处理交互、响应锁、分析锁和反思队列；`conversation_id` 只参与人格解析，不作为关系键。后台分析、命令反思、Web 反思及档案重建共享同一分析锁。同一目标深轮次只允许一次代码结算，应用阶段再次拒绝 `target_round <= last_deep_round`。重置在分析锁内清空该 UMO 的关系状态、消息、待处理交互、反思队列及其正式绑定。

调试页面位于 `astrbot_plugin_companion_lite_v2/page/debug`。页面包含“关系档案 / 启停管理”双视图：启停管理是唯一修改单 UMO 启用状态的入口；关系档案不再放置重复开关。档案主视图采用编辑式信息层级，依次展示三维与感受追踪、关系侧写、六轮互动节奏、五标签语义投影、消息时间线和默认折叠的工程诊断。诊断内保留严重筛查、确认模型、模型观察到代码裁决及缓存用量的完整数据。页面每五秒静默同步，数据未变化时不重绘；同步会保留滚动、页签、折叠、消息展开和交互焦点，选中文字或操作输入框时继续暂停更新。

`observe` 模式额外为未正式绑定和曾绑定窗口提供“保留消息并重建档案”。它从第 2 轮开始重新运行全部有效轻/深分析，所有步骤成功且期间没有任何新消息或状态变化时，才原子替换关系档案；失败时原档案保持不变。正式绑定窗口在任何小模型调用前拒绝重建，避免重放首次绑定的一次数值托底。这里的档案是关系档案，不复制或修改 LivingMemory 保存的用户事实。

## 运行

V1 当前仅作为残留代码和设计参考，不被视为可运行依赖或回退实例。V2 默认使用 `observe` 模式，仅记录、分析和编译预览，不修改主人格请求；完成真实对话观察后再独立切换到 `active`。
