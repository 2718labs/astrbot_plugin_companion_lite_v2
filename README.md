# CompanionLiteV2

CompanionLiteV2 是一个面向 AstrBot 私聊场景的轻量关系侧车。它不替代主人格，也不保存用户事实；它只观察用户如何对待 agent 的投入、表达和边界，再把关系处境编译成简短自然语言，影响主人格本轮愿意投入多少、保持多远以及是否需要立界限。

当前稳定版本：`2.0.0`。新安装默认使用 `observe`；完成验证后可切换为 `active`，让关系说明实际进入主模型请求。

## 为什么另做 V2

V1 在多轮重构后已经不再被视为可运行基线。V2 使用独立目录、配置、命令、数据库和 Web 路由，从精简模型重新开始：

- 小模型只观察证据，不决定姿态、权限或绝对数值。
- 关系升级、修复、三维变化和严重事件例外全部由代码裁决。
- 主模型只接收自然语言处境，不接收裸标签、评分、事件编号或分析提示词。
- LivingMemory 负责“这个用户是谁、发生过什么”，V2 只负责“这轮愿意投入多少、保持什么距离”。
- V2 不读取、迁移或修改 V1 和 LivingMemory 的数据。

## 一轮对话如何产生作用

```text
用户私聊消息
  -> 保存消息（单条最多 400 字，超长保留首尾）
  -> 本地严重候选筛查
       -> 正常消息：零次额外 LLM 调用
       -> 命中候选：5 秒小模型确认，失败开放
  -> 按会话覆盖、当前对话、默认人格三级解析人格 ID
  -> 读取当前关系档案和该人格的唯一绑定状态
  -> 代码编译不超过 340 字的自然语言上下文
  -> observe：只保存预览
     active：追加一个临时内容块给主模型

主人格回复完成
  -> 保存回复并配成完整来回
  -> 第 2/4/8/10 轮：轻分析最近两个完整来回
  -> 第 6/12/... 轮：深分析最近最多 20 条消息
  -> 小模型提交证据标签
  -> 代码统一更新姿态、问题阶段和三维关系
```

分析发生在回复完成后，所以结果只指导后续轮次。

## 关系模型

V2 只保留三维数值、一个姿态和一个主导问题。

| 字段 | 范围 | 含义 |
|---|---:|---|
| `familiarity` | `0..100` | 对这个人与相处方式的了解，只升不降 |
| `trust` | `0..100` | 是否已经形成可以依赖的默契 |
| `affinity` | `-100..100` | agent 对当前互动的主观亲和或疏离 |

默认信任为 `50`，语义是“暂无明显不信任，但尚未建立可依赖的默契”，不代表已经信任。

熟悉度阶段：

| 范围 | 阶段 |
|---:|---|
| `< 10` | 陌生 |
| `10..34` | 认识一些 |
| `35..64` | 熟悉 |
| `>= 65` | 长期熟悉 |

熟悉度每周期只接受 `0/+2/+5`；信任和亲和只接受 `-10/-4/-2/0/+2`。自然演化最早第 12 轮才允许脱离陌生阶段；管理员明确执行正式绑定是唯一例外。

关系姿态：

| 姿态 | 行为权限 |
|---|---|
| `normal` | 结合熟悉度、信任和亲和决定投入与态度 |
| `reserved` | 简单问题至多给结论或一个要点，费力任务可拒绝 |
| `guarded` | 默认拒绝非必要任务，不先附赠答案 |
| `disengaged` | 不承接普通任务，是否回应边界或修复由人格决定 |

主导问题只允许：

- `one_sided`
- `ignored_expression`
- `boundary_violation`
- `degradation`
- `coercion`

问题阶段只允许 `noticed`、`expressed`、`repairing`。

## 单向互动的升级节奏

- 第 2 轮首次确认单向互动：不改变持久姿态；若第 3 轮继续投递任务，可先指出连续索取再决定是否拒绝。
- 第 4 轮再次确认：允许后续两轮直接表达厌烦并拒绝任务。
- 第 6 轮如果对话中确实出现了 agent 的表达，而且用户仍忽视或施压：可进入 `ignored_expression / guarded`。
- 如果 agent 并未实际表达：最多进入 `one_sided / noticed / reserved`。
- 首次六轮确认单向索取时，代码固定结算为熟悉度 `+2`、信任 `-2`、亲和 `-4`。

泛泛道歉不能恢复关系。只有具体承认并接受后果，才会进入 `repairing`；至少两个完整来回没有复犯且出现相反行为后，后续深分析才可关闭问题。

## 人格级正式绑定

亲密身份不再由复杂的自动状态机推测，而由管理员在对应私聊窗口明确确认。人格 ID 的解析顺序与 LivingMemory 一致：

1. 当前 UMO 的 `session_service_config.persona_id`；
2. 当前 conversation 的 `persona_id`；
3. 当前 UMO 的默认人格 `name`。

`[%None]`、不存在的人格或解析异常都会失败关闭，不会把 UMO 第一段的显示名误当人格。下文测试统一使用 `persona-name` 作为泛化人格 ID。

每个人格只有一个正式关系席位。首次 `/companion_bond` 会把不足的三维补到熟悉度 `35`、信任 `60`、亲和 `15`，表示“已经熟悉、存在稳定信任和明确偏爱”，但不会清除当前问题、姿态或负面印象。幂等重发和解绑后重绑不会借机回血；之后信任与亲和仍可按正常分析下降。

绑定关系只允许主人格自然亲近、暧昧或使用昵称，不代表无条件服从。`guarded`、`disengaged` 和未解决问题始终优先。解绑保留三维、问题、印象和消息，只撤销正式身份；之后最多按熟人距离表达。

未绑定且熟悉度低于 `35` 时，关系尚浅却清晰预设伴侣身份或推进暧昧，可以形成 `premature_intimacy` 观察。轻分析只提醒保持自然距离；深分析每个六轮窗口最多扣亲和 `-2`，不直接建立问题或升级姿态。正式绑定中的正常亲密表达豁免，但骚扰、强迫和威胁不豁免。

## 严重事件预检

每轮主回复前先运行本地候选筛查。它只判断“是否值得复核”，不会直接定罪。

候选包括：

- 直接针对 agent 的人格贬低；
- 威胁、勒索和条件式伤害；
- 强迫服务或否定拒绝权；
- 已表达边界后仍明确继续施压。

引用块和代码块会先被排除。只有命中候选才调用严重确认小模型，输入最多 400 字，超时为 5 秒；调用超时、无效 JSON 或低置信结果均不修改关系，交给后续轻/深分析兜底。

每个用户每六轮最多确认两次，同一规范化消息去重；已有严重问题时，相同行为无需重复复核。明确且高置信的贬低、强迫或边界侵犯可以进入 `guarded`，极端威胁或重复严重侵犯可以进入 `disengaged`。

## 陌生人的投入尺度

陌生用户先得到两三句简单总览：

- 给出当前问题的关键结论或方向，不主动写成长教程、完整推导、路线大全或额外资料；
- 认识一些后可以解释几个核心点，熟悉后逐步恢复完整但简练的回答；
- 负亲和会进一步降低帮助意愿，且优先于熟悉度；低信任单独限制额外投入；
- 连续六轮只索取任务且不承接互动后，新任务全部拒绝，只保留对具体承接或修复的回应。

随着熟悉度增长且用户持续承接互动，主人格才逐渐恢复正常展开。

## 提示词与缓存

严重确认、轻分析和深分析分别使用带版本号、字节稳定的静态系统提示。显式配置的人格参考并入深分析静态前缀；动态区只包含最小关系状态和截断后的对话。

主人格采用双层协议。字节稳定的 `companion_protocol` 前置到 system prompt，统一解释字段职责和执行顺序；每轮变化的 `companion_state` 通过临时用户内容块追加到当前消息之后，不破坏稳定系统前缀。协议要求先决定是否愿意回答，拒绝时不得先交付大部分答案。

动态状态使用固定的 260–340 字预算，并始终保留五个标签：

1. `投入`：本轮回答多少；
2. `关系`：与当前用户站多近；
3. `处境`：待处理的具体互动事件；无活动事件时明确写“当前无待处理的具体互动事件”，不代表没有负面感受；
4. `感受`：深分析生成并持续修订的第一人称内心态度；
5. `表达`：语气、情绪表达权限和轻提醒。

Companion 不注入人格侧的和善、安抚或措辞护栏。AstrBot 与底层模型自身规则仍独立生效，但不由 Companion 重复声明。

关系总结和问题摘要只供反思与调试。第一人称感受会经过清洗和 40 字限制后作为 `<感受>` 注入主人格，例如“我不想再理他了”；深分析被明确要求写人格内心态度，不写“我观察到互动偏单向”式分析报告。

调试数据会记录提示词版本、动态输入字符、模型标签、代码裁决以及提供商返回的 cached/uncached/output tokens；不会保存完整分析提示词副本。未提供缓存统计的模型会显示“提供商未报告”。

## 安装与共存

可从 [GitHub Releases](https://github.com/6TBWhite/astrbot_plugin_companion_lite_v2/releases) 下载稳定版本，或在 AstrBot 插件管理页通过仓库地址安装：

```text
https://github.com/6TBWhite/astrbot_plugin_companion_lite_v2
```

插件目录：

```text
data/plugins/astrbot_plugin_companion_lite_v2
```

数据目录与数据库：

```text
data/plugin_data/astrbot_plugin_companion_lite_v2/
└── companion_lite_v2.db
```

V2 与 V1 可以同时保留源码，但不能同时向同一轮主模型注入关系上下文。推荐流程：

1. V2 保持 `observe`，先观察真实对话和回放结果。
2. 检查姿态、问题、三维数值和下一轮编译预览。
3. 确认其他关系插件不会注入冲突指令。
4. 再将 V2 切换为 `active`。

更新文件后，需要在 AstrBot WebUI 的“插件 → AstrBot 插件”中重载 CompanionLiteV2，或重启 AstrBot。

## 配置

| 配置项 | 默认值 | 说明 |
|---|---:|---|
| `operation_mode` | `observe` | `observe` 只分析；`active` 启用上下文注入 |
| `enable_message_capture` | `true` | 捕获私聊完整来回 |
| `min_message_length` | `1` | 进入缓冲的最短字符数 |
| `max_message_length` | `400` | 单条用户消息和主人格回复的入库上限 |
| `max_buffer_rounds` | `24` | 每用户保留的完整来回数 |
| `reflection_provider_id` | `""` | 留空使用当前默认模型提供商 |
| `persona_prompt` | `""` | 深分析使用的稳定人格参考 |
| `max_context_chars` | `340` | 主人格关系上下文预算，可配置范围 `260..340` |

## 管理员命令

命令只在私聊中使用：

| 命令 | 功能 |
|---|---|
| `/clv2_status` | 查看当前会话关系状态和最近编译文本 |
| `/clv2_reset` | 清空当前完整 UMO 的 V2 状态、消息、待处理交互和正式绑定 |
| `/clv2_reflect` | 尝试运行当前轮次的深分析 |
| `/companion_bond` | 将当前窗口设为当前人格唯一正式关系 |
| `/companion_unbond` | 解除当前窗口的正式身份，保留全部相处状态 |

## 调试页

地址：

```text
http://<AstrBot地址>/#/plugin-page/astrbot_plugin_companion_lite_v2/debug
```

调试页按完整 UMO 列出私聊档案，例如：

```text
bot:FriendMessage:test-user
```

关系档案、消息缓冲、待处理交互、响应锁、分析锁和反思队列都按这个完整 UMO 隔离。一份完整 UMO 对应一份 Companion 缓存；同一用户若通过不同 UMO 进入，会得到相互独立的档案。AstrBot `conversation_id` 只用于解析当前人格，不作为关系缓存键。

页面展示：

- “关系档案 / 启停管理”双视图；管理视图可总览、搜索、筛选并逐项切换最多 1000 个已知 UMO；
- 三维数字及对应自然语言；
- 编辑式“关系侧写”，集中呈现姿态、阶段、正式身份、当前问题、关系总结和第一人称感受；
- “互动节奏”以六轮进度显示最近分析、下一次大总结、注入状态及当前 UMO 操作；
- “语义投影”把下一轮预览与上一轮实际快照解析为五标签，并可展开、复制原始提示词；
- 最近消息以纵向互动时间线展示；
- 本地严重筛查、模型观察、代码裁决和缓存 token 默认收进“工程诊断”；
- 启停只在独立管理视图操作，关系档案不再提供单会话开关。

页面空闲时每五秒自动同步，并保持滚动位置、工程诊断与原始提示词的展开状态、语义投影页签、消息展开状态和新交互控件焦点。数据没有变化时不会重绘；选中文字或操作输入框时自动暂停同步，避免复制内容时选区被刷新打断。

`observe` 模式下，未正式绑定和曾绑定的窗口可使用“保留消息并重建档案”。它会从第 2 轮开始重新分析全部有效轮次；只有所有分析成功，且期间没有新消息或状态变化时，才原子替换档案。正式绑定窗口禁止重建，避免一次性绑定托底被错误重放。失败不会破坏原状态。

## 存储

V2 只创建四张业务表：

- `companion_state`
- `message_buffer`
- `pending_interaction`
- `companion_bond`

V2 不读取、迁移或修改 V1 的 `companion_lite.db`，也不写入 LivingMemory 数据。
